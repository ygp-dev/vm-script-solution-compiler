# 验收用例与实施路线

## 1. 首版验收用例

### E01 环境检测

- 当前环境包含 `MVDALGO_DEV_ENV`。
- 应解析 VM 根目录、4.4.0 版本和 GlobalScript 目录。
- 不允许硬编码用户机器路径。

### E02 全局脚本 Create

- 需求：默认执行空流程。
- 输出：仅必要结构与 GlobalScript。
- 验证：JSON、NUL、引用、parse、VM 编译。

### E03 ShellModule Create

- 输入：A、B，类型 float。
- 输出：Sum，类型 float。
- 逻辑：`Sum=A+B`。
- 验证：DynamicIO、ShellContent、模块入口、VM 运行结果。

### E04 PyShellModule Create

- 输入：A、B，类型 int。
- 输出：Sum，类型 int。
- 不使用第三方库。
- 验证：`moduleVar` 访问、返回码、VM 运行结果。

### E05 Python 第三方库阻断

- 需求包含未部署的 native Python 包。
- 预期：不安装，返回 `PYTHON_RUNTIME_UNCONFIRMED` 或依赖缺失报告。

### E06 Patch 清空标定点

- Base SOL 包含流程和 `N点标1`。
- 注入脚本调用 `SetValue("Clear", "")`。
- 验证模块/参数存在，只新增预期脚本、IO、连线和订阅。

### E07 Create 引用不存在模块

- Create 模式引用 `N点标1`，模板中不存在。
- 预期：`EXTERNAL_MODULE_NOT_AVAILABLE`，不输出假成功 SOL。

### E08 输入输出类型冲突

- 输出定义 float，但脚本/订阅目标为 string。
- 预期：`IO_TYPE_MISMATCH`。

### E09 重复构建

- 相同 requirement 构建两次。
- 结构 diff 仅允许 GUID、时间等声明过的非确定字段变化。

### E10 输入保护

- Patch 构建失败。
- 原 SOL 哈希必须保持不变。

## 2. 错误码

| 错误码 | 说明 |
|---|---|
| `VM_HOME_NOT_FOUND` | 环境变量无法定位 VM |
| `VM_VERSION_MISMATCH` | VM、模板或输入方案版本不匹配 |
| `INVALID_REQUIREMENT` | IR 不符合 schema |
| `UNSUPPORTED_SCRIPT_CARRIER` | 脚本载体不支持 |
| `SCRIPT_TEMPLATE_CORRUPTED` | 解包模板或模块帧损坏 |
| `EXTERNAL_MODULE_NOT_AVAILABLE` | 当前方案不存在被脚本引用的模块 |
| `MODULE_PARAMETER_NOT_FOUND` | 模块参数不存在或不可写 |
| `EXPRESSION_TYPE_MISMATCH` | 表达式类型与目标端口不一致 |
| `RESULT_NOT_FOUND` | 表达式引用了尚未声明的操作结果 |
| `SCRIPT_PRECOMPILE_FAILED` | 源码未通过 VM 方法程序集或 VM Python 的离线预编译 |
| `IO_TYPE_MISMATCH` | 输入输出/订阅类型不一致 |
| `REFERENCE_TYPE_UNCONFIRMED` | DLL 引用类型无可靠映射 |
| `PYTHON_RUNTIME_UNCONFIRMED` | VM Python 环境未确认 |
| `SOL_PARSE_FAILED` | 输出无法解析 |
| `SOL_VALIDATION_FAILED` | 结构或语义校验失败 |
| `BASE_SOLUTION_MISMATCH` | Patch 命令与 Requirement 指向不同基底 |
| `MODULE_TYPE_MISMATCH` | Patch 同名目标的载体类型不一致 |
| `RESOURCE_MANIFEST_INCOMPLETE` | VM 资源文件未全部纳入哈希清单 |
| `VM_RUNTIME_VALIDATION_REQUIRED` | 尚未在目标 VM 实机验证 |

## 3. 开发阶段

### M0：规格冻结

- 完成需求、IR、错误码和验收用例。
- 明确 Create/Patch 边界。

### M1：Compiler Core 骨架

- 环境检测。
- Requirement schema 与模型。
- 任务目录、日志、哈希和报告。
- 解包模板物化。

### M2：全局脚本

- 写入 GlobalScript JSON、源码和引用。
- Create/Patch。
- parse/inspect 校验。

### M3：ShellModule

- 模块复制、ID/GUID/UI。
- ShellContent。
- Input/Output/DynamicIO。
- 连线与订阅。

### M4：PyShellModule

- Python 默认入口。
- DynamicIO 与变量访问。
- 第三方包清单和环境验证。

### M5：Agent Adapter

- Prompt → Requirement IR。
- Schema 验证与缺失项追问。
- 编译错误反馈修复，但不直接操作 SOL。

### M6：MCP/UI

- MCP 8 tools：环境、IR plan/build/patch/validate，以及提示词 plan/build/patch。
- Desktop UI 调用同一 Core，支持 Requirement 文件与自然语言两类入口。

### M7：类型与确定性操作

- 完整 VM 端口类型、变量 Getter/Setter 和表达式 AST。
- 模块默认独立，只有显式 connections 建图。
- 流程控制、通信、模块参数、变量和 pointset 操作。

### M8：经典 Patch 与预编译

- 经典 SOL/FAQ 证据 catalog 与模块参数门禁。
- ModuleFrame v4/v7 安全 Patch。
- VM 4.4 方法程序集离线 C# 编译和 VM Python 语法验证。
- `tests/run-m8-smoke.ps1` 覆盖类型方法、v4 基底保护、警告增量和未知参数阻断。

## 4. 首版完成定义

首版不是“能生成一个 ZIP”即完成，而是：

1. E01–E10 均有自动测试或明确的 VM 手工验证记录。
2. CLI 的 Create/Patch/Validate 可运行。
3. 全局 C#、ShellModule、PyShellModule 各有成功 SOL。
4. 正式发布包不包含 `.sol` 模板。
5. 无法确认的接口会阻断并形成稳定错误码。
6. 文档、JSON schema、实际代码模型和 CLI 参数保持一致。
7. CLI、Desktop、MCP 三个发布产品可脱离源码树定位资源；Desktop 内置 Agent/Node/Worker，且发布包中 `.sol` 数量为 0。
