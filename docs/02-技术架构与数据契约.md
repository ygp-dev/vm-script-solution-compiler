# 技术架构与数据契约

## 1. 总体架构

```text
Prompt
  ↓
Agent Adapter
  ↓
Requirement IR (JSON)
  ↓
Planner + Semantic Validator
  ↓
Build Plan
  ↓
Script Generators
  ↓
SOL Compiler Core
  ↓
Parse / Inspect / Structural Diff
  ↓
SOL + Contract + Report
```

## 2. 技术建议

- 操作系统：Windows x64。
- Compiler/CLI：C#，建议 `net8.0-windows`，发布为 x64 self-contained EXE。
- 生成的 VM C#：.NET Framework 4.6.1/x64 兼容子集。
- JSON：`System.Text.Json` 仅用于 Agent/Compiler 自身，不进入 VM 脚本。
- SOL 解析与回写：复用并逐步内聚现有 VMSolutionParser 能力。
- Agent Provider：接口化，首版允许没有模型，仅支持 `--spec` 确定性编译。
- MCP：独立适配项目，不引用 SOL 二进制实现细节。

## 5. 编译计划

Planner 输出只允许使用已定义动作：

```json
{
  "actions": [
    {"kind":"verifyModule","path":"流程1.N点标1"},
    {"kind":"addScriptModule","carrier":"csharp-module","procedure":"流程1","name":"清空标定点"},
    {"kind":"configureIo","scriptId":"clear-points"},
    {"kind":"writeScript","scriptId":"clear-points","source":"generated/UserScript.cs"},
    {"kind":"addConnection","from":"流程1.N点标1","to":"流程1.清空标定点"},
    {"kind":"rebuildModuleFrame"},
    {"kind":"repackSolution"},
    {"kind":"parseAndValidate"}
  ]
}
```

Agent 不得输出任意 XML/二进制写入动作；Planner 根据 IR 生成白名单动作。

## 6. 核心接口

```csharp

    VmEnvironment Detect();

    ValidationResult Validate(CompileRequirement requirement, SolutionModel? baseSolution);

{

```

## 7. 资源策略

- 发布包内不得包含 `.sol`。
- 模板保存为解包目录及必要的二进制片段。
- 资源必须带 manifest：VM 版本、来源哈希、模块类型、帧版本和验证状态。
- 构建时复制到任务临时目录并物化工作 SOL。
- 每个任务结束清理临时明文脚本和中间 SOL，保留明确交付物。

## 8. 版本策略

- 首版资源：VM 4.4.0。
- 需求中的 VM 版本必须与资源 manifest 匹配。
- 小版本兼容不能只依赖版本字符串；需按 ModuleFrame 版本、模块类型和脚本入口验证。
- 将来按 `resources/vm/<version>/` 管理多版本资源。
