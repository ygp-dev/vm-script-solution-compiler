# 算子二次开发知识接入与脚本边界

## 来源与定位

项目收录了 V 社区文章[《VM运行界面之清空图像》](https://www.v-club.com/home/article/11028)。文章发布于 2026-06-10，描述的是 VM 3.4.0 的运行界面场景。它被作为 Agent 的“模式参考”接入，不作为 VM 4.4 API、端口类型或方法签名的证据。

## 可复用的模式

文章的需求是：开始新产品检测前清理多图像控件，随后逐张保留新图像。文章记录了三种尝试：

1. 运行界面的多图像控件没有直接清空接口；
2. 绑定仿射模块的输出图像属性只读；
3. 绑定仿射模块的输入图像可以写入。

最终采用一次执行的分支流程，让脚本向每个已经确认的仿射模块输入写入背景图，从而触发运行界面更新。

文章的代码截图还给出了调用形态：用 `OpenCvSharp.Cv2.ImRead` 读取灰度图，创建 `InputImageData`，填写 `InImage`、`InImageHeight`、`InImageWidth`、`InImagePixelFormat` 等默认字段及像素数据；再通过 `VmSolution.Instance[流程名.模块名] as TMVSAffineTransformModuTool` 获取仿射工具，调用 `ModuParams.SetInputImage(inputImageData)` 写入输入图像。

这些名称只作为 VM 3.4.0 文章样例保留。VM 4.4 生成前仍必须确认对应的算子/平台 DLL、版本、x64 架构、OpenCvSharp 依赖和目标 ShellModule 的预编译结果；项目不会把它们当作内置 API。

## Agent 规则

- Patch 任务先 `vm_inspect_solution`，确认显示模块、仿射模块、真实数据源、输入图像参数和可写方向。
- 只有解析结果、项目证据或用户提供的实机样例确认了目标，才生成 `setModuleValue` 或源代码写入；不能因为用户说“清空”就猜一个 `Clear` 或 UI 清空 API。
- 文章截图中的算子 SDK 类型、方法名、构造函数和端口类型不能直接复制到 ShellModule/PyShellModule。
- 算子 SDK DLL 默认属于外部宿主/二次开发边界。只有项目程序集目录和预编译结果同时确认可加载时，才允许作为目标 ShellModule 依赖。
- 背景图写入是状态修改工作流，不是 VM 实机验收。编译完成后必须告诉用户需要在 VM 中确认显示、保存、关闭和重开；目标缺失或类型不明时返回结构化错误，禁止静默输出白图。

具体的机器可读证据位于 `resources/vm/4.4.0/secondary-development-knowledge.json`，其中标记了文章版本范围、置信度和不适用条件。
