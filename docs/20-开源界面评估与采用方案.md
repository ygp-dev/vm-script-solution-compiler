# 开源 Agent 界面评估与采用方案

## 结论

附件截图对应的是 GitHub Copilot 官方桌面应用风格。GitHub 公开的 `github/app` 仓库是发布、变更记录和 issue 仓库，官方说明应用源码位于其他位置，因此不能直接复制其实现。

本项目采用“开源布局模式 + 现有 VM Agent 后端”的方式：保留当前 WPF Desktop、Pi Runtime、Domain Worker 和确定性 Compiler Core，只把首页、侧栏、会话区和输入区向成熟的 Agent 工作台布局靠拢。这样不会把 VM 领域 Agent 替换成 OpenCode，也不会引入第二套模型或 MCP 调用链。

## 候选项目

| 项目 | 许可证 | 可复用部分 | 不能直接接入的原因 |
| --- | --- | --- | --- |
| [Palot](https://github.com/ItsWendell/palot) | MIT | Electron/React 的侧栏、会话分组、Home、实时工具卡片和输入区布局 | UI 通过 `@opencode-ai/sdk` 绑定 OpenCode Server；直接替换会丢失 VM Agent 的 Pi/Domain Worker 协议 |
| [OpenChamber](https://github.com/openchamber/openchamber) | MIT | Desktop/Web/PWA 工作区、会话目标、预览和结果审阅 | 核心运行时依赖 OpenCode，功能面远大于当前 VM Desktop |
| [cdesktop](https://github.com/cdesktop-ai/cdesktop) | Apache-2.0 | 会话侧栏、聊天/终端/差异/预览工作区和多 Agent 选择 | 当前主要是 Web UI，Tauri Desktop 尚未发布；后端是 Rust + 固定 CLI 适配器 |

## 本项目的接入边界

- 不复制 GitHub Copilot 商标、图标或专有资源。
- 不把 Palot/OpenChamber 的 OpenCode SDK 引入本项目。
- 复用公开项目验证过的信息层级：Home、My Work/结果、Automations/任务、Search/产物检索、Sessions、项目/分支上下文和底部 Prompt Composer。
- 所有生成、Patch、预编译、SOL 物化和 VM 人工确认仍走现有确定性链路。
- 外部项目只作为 UI 参考；如果未来复制具体 MIT/Apache 代码，必须同时保留原项目许可证和 NOTICE。

## 验收要求

1. 侧栏可切换当前任务、结果产物、设置，并保留最近会话。
2. Home 入口能直接开始自然语言任务，支持 Create/Patch、基底方案和项目上下文。
3. 任务完成后能从 Sessions/结果产物进入 SOL、报告和生成源码。
4. UI 调整不能改变 Agent RPC、Domain Worker、MCP 或 Compiler Core 的协议。
5. Desktop smoke、Agent smoke、MCP smoke 和独立发布 smoke 继续通过。
