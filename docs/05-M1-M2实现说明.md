# M1-M2 实现说明

## 已实现

- .NET 8 Compiler Core 与 CLI 骨架。
- 按 `VISIONMASTER_HOME`、`VM_HOME`、`MVDALGO_DEV_ENV`、`PATH` 顺序检测 VM 环境。
- Requirement IR 强类型模型、严格字段检查和基础语义校验。
- VM 4.4.0 资源 manifest、版本和 SHA-256 校验。
- 每次构建使用独立任务目录，不覆盖输入 SOL。
- 从解包资源临时物化 SOL；仓库和发布资源不保存 `.sol` 模板。
- GlobalScript Create：删除 ShellModule/PyShellModule，写入 UTF-8、NUL 结尾的 `GlobalScript_0`。
- GlobalScript Patch：复制输入 SOL 后替换全局脚本，保留原业务模块和已存在引用。
- 生成 `requirement.json`、`build-plan.json`、`script-contract.json`、源码、解析结果、检查结果和构建报告。
- 使用内置 VMSolutionParser 执行 parse/inspect 验证。

## 当前边界

- VM 4.4 每个 Requirement 只接受一个 `global-csharp` 脚本。
- 后续里程碑已支持从结构化 `operations` 或完整 `source` 生成并离线编译全局脚本；本条替代 M2 初始阶段的默认模板限制。
- ShellModule 额外 DLL 优先使用证据目录；自定义 DLL 必须提供 `path + referenceType: 4`。GlobalScript 自定义引用仍要求独立的同版本 `ScriptRefences` 类型证据。
- ShellModule、PyShellModule 和 DynamicIO 已在后续 M3、M4 实现；完整状态见 `07-完整实现与验收状态.md`。
- M1/M2 当时的 `runtimeValidated=false` 为历史阶段状态；2026-07-15 最终候选完成用户实机验收，当前 manifest 为 `runtimeValidated=true`。
