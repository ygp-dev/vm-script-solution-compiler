# VM Script Solution Compiler 完整需求规格

## 1. 产品定义

`VM Script Solution Compiler` 是一个面向 VisionMaster 4.4+ 的 Windows 本地工具。它把结构化脚本需求确定性地编译为 `.sol`，并可由 AI Agent 将用户自然语言先转换为结构化需求。

产品由四层组成：

1. **Compiler Core**：JSON 中间表示到 SOL 的确定性编译器。
2. **CLI**：本地命令行入口，是首版正式交付入口。
3. **Agent Adapter**：提示词到 JSON 中间表示，只负责理解需求和生成业务代码。
4. **MCP/UI Adapter**：已实现入口，调用同一个 Compiler Core，不绕过 IR 验证和结构校验。

AI 不直接编辑 `VmServer.xml`、`MoudleFrame`、`UiParamData` 或 ZIP；所有格式修改由编译器完成。

## 2. 产品目标

- 根据提示词生成全局 C#、流程内 C# 或流程内 Python 脚本。
- 根据提示词配置脚本输入、输出、默认值、依赖和执行方式。
- 生成新脚本方案，或把脚本安全注入已有业务方案。
- 生成可追溯的源码、需求契约、构建计划、SOL 和验证报告。
- 让相同输入产生可复现的 SOL 结构和构建结果。
- 发现不确定接口、版本或模块参数时阻断，而不是猜测。

## 3. 非目标

- 首版不生成普通视觉算法流程。
- 首版不自动安装 Python 包或第三方 DLL。
- 不绕过 SOL/脚本密码。
- 不修改 VisionMaster 安装目录。
- 不在构建机上直接执行用户生成的 C# 或 Python 代码。
- 不保证未经目标 VM 打开、编译和运行的 SOL 已完成生产验收。

## 4. 两种编译模式

### 4.1 Create：生成纯脚本方案

从内置的解包结构生成新 SOL。允许包含：

- 一个或多个 `GlobalScript_0` 支持范围内的全局脚本配置；VM 4.4 当前按一个全局脚本文件处理。
- 一个或多个 `ShellModule`。
- 一个或多个 `PyShellModule`。
- VM 必需的 Solution、Procedure、UiParamData 等结构。

不包含普通视觉算法模块。

### 4.2 Patch：注入现有业务方案

输入一个已有 SOL，在保留其模块和参数的前提下：

- 新增/替换全局脚本。
- 新增/替换 ShellModule/PyShellModule。
- 增加 DynamicIO、订阅和执行连线。
- 生成新 SOL，不覆盖原文件。

CLI/MCP 的 Patch 调用可由 `--base`/`baseSolution` 参数提供基底，因此 Requirement 的 `task.baseSolution` 可省略；若命令参数和 Requirement 同时提供，两者必须解析为同一路径，否则返回 `BASE_SOLUTION_MISMATCH`。同流程、同显示名、同载体的脚本执行原位替换；同名但载体不同会被阻断。

涉及以下调用时应优先使用 Patch：

```csharp
CurrentProcess.GetModule("N点标1").SetValue("Clear", "");
```

因为 `N点标1` 必须存在于目标业务方案中。Create 模式若引用不存在的业务模块，应返回 `EXTERNAL_MODULE_NOT_AVAILABLE`，除非用户明确将其声明为部署时依赖。

## 5. 支持的脚本载体

### 5.1 全局 C# 脚本

- SOL 位置：`SolutionFile\GlobalScript_0`。
- 默认类型：`UserGlobalScript : UserGlobalMethods, IScriptMethods`。
- 必需入口：`int Init()`、`int Process()`。
- 可选回调：结果回调、全局通信接收回调。
- 适用：初始化、流程控制、通信、模块参数操作、结果读取、方案保存/加载。
- 目标框架：.NET Framework 4.6.1，x64 基线。

### 5.2 C# 用户脚本模块

- 模块：`ShellModule`。
- 脚本参数：`ShellContent`。
- 默认类型：`UserScript : ScriptMethods, IProcessMethods`。
- 必需入口：`void Init()`、`bool Process()`。
- 输入输出：`Input`、`Output`、`DynamicInData`、`DynamicOutData`。
- 适用：流程内计算、数据转换和模块控制。

### 5.3 Python 用户脚本模块

- 模块：`PyShellModule`。
- 脚本参数：`ShellContent`。
- 必需入口：`Process(data) -> int`。
- 初始化对象：`moduleVar`、`globalVar`、`localVar`。
- 输入只读，输出只写；全局和局部变量使用 `GetValue/SetValue`。
- 适用：Python 计算及已部署第三方库调用。

## 6. 环境检测

程序启动必须先检测 VM，优先级：

1. `VISIONMASTER_HOME`
2. `VM_HOME`
3. `MVDALGO_DEV_ENV` 的父目录
4. `PATH` 中的 `VisionMaster<版本>` 根目录

有效 VM 根目录至少包含：

```text
Applications
Development
MVDAlgorithmSDK
```

同时确认：

```text
<VM_ROOT>\Applications\GlobalScript
```

环境快照必须写入构建报告，包括 VM 根目录、版本、全局脚本组件、Platform SDK、Algorithm SDK 和目标架构。检测失败返回 `VM_HOME_NOT_FOUND`，不扫描整个磁盘。

## 7. 提示词需求

用户可使用自然语言，例如：

> 生成一个用户 C# 脚本，输入 ClearTrigger。当值为 1 时清空流程中 N点标1 的标定点，输出 Result。

Agent 必须转换为结构化中间表示，并明确：

- 编译模式：Create/Patch。
- VM 版本。
- 脚本载体。
- 所属流程和执行顺序。
- 输入、输出和类型。
- 模块操作。
- 第三方依赖。
- 错误处理与成功条件。

缺少的信息若可安全默认则记录默认值；会改变 SOL 行为的缺失信息必须向用户确认或阻断。

## 8. 输入输出类型

首版至少规划支持：

- `bool`
- `int`
- `float`
- `string`
- `image`

数组、点、线、圆、区域、姿态等 VM 复合类型在取得成功 DynamicIO 样本后扩展。编译器必须做端到端类型检查：契约类型、脚本类型、DynamicIO XML、订阅源/目标类型一致。

## 9. CurrentProcess 与模块操作

中间表示需要支持：

- `getModule`
- `setModuleValue`
- `getModuleValue`
- `runProcedure`
- `setProcedureInput`
- `get/setGlobalVariable`
- `get/setLocalVariable`
- `saveSolution`
- `loadSolution`

每个操作必须记录目标流程、模块显示名或完整路径、参数名、值类型、执行时机和错误策略。

Patch 模式必须从输入 SOL 验证模块存在、名称唯一、参数可写。Create 模式不得假设业务模块存在。

## 10. 第三方依赖

### C# DLL

- 必须记录 DLL 文件名、版本、目标框架、CPU 架构和递归依赖。
- 只能使用 .NET Framework 4.6.1/x64 可加载的程序集。
- `ScriptRefences.refrencesType` 只能复制同版本已验证记录，不得猜测。
- 构建报告必须区分“编译引用存在”和“VM 运行时已验证”。

### Python 包

- 不在脚本运行期间执行 `pip install`。
- 依赖必须预部署到 VM Python 的搜索路径。
- native `.pyd`/DLL 必须匹配 VM Python 版本、位数和 ABI。
- 系统 Python 可导入不能证明 VM Python 可导入。
- 未确认解释器或依赖路径时返回 `PYTHON_RUNTIME_UNCONFIRMED`。

## 11. SOL 构建约束

- 正式产品仓库和发布包不包含 `.sol` 模板文件。
- 内置资源使用解包后的 `SolutionFile` 结构、脚本源码模板和必要模块帧数据。
- 构建过程中可在临时工作目录物化 `.sol`。
- 最终输出 SOL 由 `VmServer.xml`、`MoudleFrame`、`UiParamData`、`GlobalScript_0` 等一致构成。
- 二进制参数长度变化时必须重建 ModuleFrame。
- 新增/删除模块时必须同步处理流程归属、执行连线、订阅、UiParamData、GUID 和模块 ID。
- 输入 SOL 永不原地覆盖。

## 12. 交付物

每次构建输出独立目录：

```text
outputs/<task-id>/
├─ result.sol
├─ requirement.json
├─ build-plan.json
├─ script-contract.json
├─ generated/
│  ├─ GlobalScript.cs
│  ├─ UserScript.cs
│  └─ UserScript.py
├─ validation/
│  ├─ parse-result.json
│  └─ inspect-result.json
└─ build-report.md
```

只生成实际使用的源码文件。

## 13. CLI 需求

首版命令：

```powershell
vm-script-compiler env
vm-script-compiler plan --spec requirement.json
vm-script-compiler build --spec requirement.json --output <dir>
vm-script-compiler patch --base input.sol --spec requirement.json --output <dir>
vm-script-compiler inspect --file input.sol
vm-script-compiler validate --file result.sol
```

后续 Agent 命令：

```powershell
vm-script-agent build --prompt "..." --output <dir>
vm-script-agent patch --base input.sol --prompt "..." --output <dir>
```

所有命令支持机器可读 JSON 输出和稳定退出码。

## 14. 安全与可追溯性

- 不执行生成代码。
- 不调用网络下载依赖。
- 不修改输入 SOL、VM 安装目录或用户 DLL。
- 构建报告记录输入哈希、模板版本、工具版本、VM 环境和所有修改动作。
- 日志不得输出密码、私钥或未脱敏通信数据。
- 加密 SOL 需要用户明确提供密码；密码不写入报告。

## 15. 验收标准

- 环境检测在当前 VM 4.4.0 安装上成功。
- Create 模式能分别生成全局 C#、ShellModule、PyShellModule SOL。
- Patch 模式能向业务 SOL 注入脚本且不改变无关模块。
- 基础输入输出能生成正确 DynamicIO 并通过类型校验。
- 输出 SOL 能被 parse 与 inspect，结构 warnings 为零，且 ZIP 条目名符合 VM 4.4 反斜杠约束。
- 同一需求重复构建得到等价结构；随机 GUID/时间字段在报告中解释。
- VM 4.4 中完成打开、编译、单次/连续运行、参数读写、保存和重开。
