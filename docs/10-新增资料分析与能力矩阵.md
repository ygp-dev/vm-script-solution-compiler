## 已确认的 ShellModule 类型

官方 `ScriptDefine` 与 `GenerateUserPropertyCs` 共同确认以下端口类型：

- 基础：`int`、`float`、`string`、`byte`
- 数组：`int[]`、`float[]`、`string[]`
- 图像：`IMAGE`
- ROI/几何端口：`ROIBOX`、`ROIBOX[]`、`ROIANNULUS`、`ROIPOLYGON`、`POINT`、`LINE`、`FIXTURE`、`Rect`、`ELLIPSE`
- Circle：方法程序集支持 `CircleData[]` 变量 Getter/Setter，但 VM 4.4 ShellModule UI 无 Circle 端口选项，不能作为 Input/Output 生成。
- 点集：`pointset`

经典 SOL 实际出现了 `float[]`、`IMAGE`、`POINT`、`ROIBOX`、`pointset`，验证了类型常量确实进入 Input/Output XML。

机读映射见 `resources/vm/4.4.0/type-system.json`。

上述完整类型映射适用于 C# ShellModule。当前项目资料没有 Python `IoHelper` 对 image、byte、ROI、几何或 pointset 的读写样本；Python 仅开放已确认的 bool/int/float/string 及对应数组，其他类型由 `PYTHON_COMPLEX_TYPE_UNCONFIRMED` 阻断，不能用 C# 证据推断 Python 行为。

## C# 端口访问规则

VM 会根据端口定义自动生成 `UserScript` partial 属性：

- 基础输入：`GetIntValue`、`GetFloatValue`、`GetStringValue`、`GetBytesValue`、`GetImageValue`、`GetRoiboxValue`
- 基础输出：对应 `Set*Value`
- 数组和复杂类型：`InternalMethods.Get*ArrayValue/Set*ArrayValue`
- 用户 Process 代码直接访问属性，例如 `Sum = A + B`。

旧的 `dynamic input = Input`/`dynamic output = Output` 已确定为错误模式。

## 模块与变量访问

- 模块：`CurrentProcess.GetModule(name).GetValue/GetArrayValue/GetParamValue/SetValue`
- 全局变量：`GlobalVariableModule.GetValue/SetValue` 或 `GetVar<Type>/SetVar<Type>`
- 局部变量：`LocalVariable.GetValue/SetValue` 或 `GetVar<Type>/SetVar<Type>`
- GlobalScript：`ExecuteProcessOnce`、`ContinuousExecuteProcess`、`StopProcessExecute`、全局变量专用 Get/Set、通信发送与回调。

## 执行图规则

脚本模块默认互不连接。`execution.order` 仅保留为脚本执行意图元数据，不再隐式创建 VM 连线。只有 Requirement 根级 `connections` 明确给出 `{from,to}` 时，SOL 编译器才调用 `setConnection`。
